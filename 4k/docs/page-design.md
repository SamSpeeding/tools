# 4K 资源页面设计

## 已确认的需求

- 在现有归档目录新增 `index.php`，提供简约、美观、直接的电影和剧集浏览页面。
- 影视资料只取自现有 `movies.json` 和 `series.json`，不引入数据库，不实时抓取来源网站。
- 提供搜索与分页，避免一次向浏览器发送整个目录。
- 按用户最新要求移除图片代理，封面仅使用原图地址直连。
- 无封面或图片最终加载失败时，可隐藏图片或显示简洁占位。
- 现有采集脚本和仅新增归档规则继续适用；页面读取归档，不改变影视资料。

## 已确认方案

1. 视觉风格
   - 深色影库，炭黑背景、暖金点缀、封面卡片，适配电脑与手机。
   - 顶部保留电影 / 剧集切换和搜索，避免堆叠筛选器。
2. 资源查看方式
   - 点击卡片打开详情面板，显示简介、影片信息和资源版本。
   - 每个有效版本提供复制磁力、打开下载；关闭详情后保留目录状态。
   - 没有资源的条目正常保留，详情显示暂无资源。
3. 图片与部署边界
   - 部署 `index.php` 与两份 JSON 即可；不要求上传已有 `img`。
   - 使用 `<img referrerpolicy="no-referrer">` 直接加载封面，不发送外站来源信息；目标优先使用归档中的 `cover.download_url`，其次 `cover.source_url`。加载失败或缺少地址时显示页面内置占位，不使用图片代理。
4. 搜索与分页
   - 每页 24 条，搜索当前分类的片名、原名、别名、导演、演员和标签。
   - 默认沿用 JSON 顺序；切换分类或更改搜索词时回到第一页。
   - 参数写入 URL，刷新或返回时可以保留浏览位置。

用户已逐项确认以上推荐方案，页面实现后认可 UI 与交互，并要求移除图片代理以验证原图直连效果。

## 已核实的性能边界

- 当前电影目录 1,874 条，约 16.4 MiB；剧集目录 259 条，约 2.6 MiB。
- 本机 PHP 8.3.30 可用，含 mbstring，未安装 APCu，默认内存上限 128 MiB。
- 本机同时解析两份 JSON 的抽测耗时约 44 毫秒、峰值内存约 74.4 MiB；这不是部署服务器的性能承诺。
- 服务端搜索和分页只输出当前页，避免将整个 JSON 传给浏览器；仍然需要解析所选分类的 JSON。
- 暂不引入数据库、索引文件或额外缓存文件。若未来规模显著增长，需重新评估读取成本。

## 实现时的必要行为

- CSS 与 JavaScript 放在 `index.php` 内，不依赖前端构建步骤或外部字体、脚本库。
- 输出文本转义；只接受规定的分类和合理页码，不允许请求参数决定任意文件路径。
- JSON 缺失或损坏时显示明确错误；搜索无结果、缺图、无资源、无效磁力分别有对应状态。
- 搜索框有清空操作，分页可直接前后翻页；详情支持键盘关闭、焦点恢复与手机滚动。
- 仅加载当前页封面，使用延迟加载及固定海报比例，减少布局跳动。
- 上线前验证 PHP 语法、实际目录分页与搜索、详情复制、图片失败回退，以及电脑和手机布局。

当前选择均易于调整，不单独建立 ADR。领域术语沿用 `CONTEXT.md` 中的站内条目、资源版本和封面。

## 直连封面 404 排查

- 用户反馈剧集封面大面积加载失败，截图中失败请求为 HTTP 404，成功样例标记来自浏览器内存缓存；用户另确认失败地址在地址栏单独打开可显示。
- 使用截图中的请求头进行 HTTP 对照，ID 66471 的封面连续两次返回 404；仅移除 Referer 后返回 200 和有效 WebP 数据。移除 Sec-Fetch-Site 而保留 Referer 仍然失败。
- 对剧集第一页 24 张封面逐张比较：带 `Referer: http://127.0.0.1:8740/` 成功 17 张、404 共 7 张；仅移除 Referer 后成功 24 张。成功结果既有 CDN HIT，也有 MISS，不是仅依靠浏览器缓存。
- 结论：观察到与请求来源相关的外链限制行为；没有源站配置权限，不能断言是哪一层配置了具体规则。不是单纯因为缺少 CORS 响应头。
- 修复：共用的封面输出函数添加 `referrerpolicy="no-referrer"`，覆盖电影、剧集与详情。仍然不使用代理，不修改 JSON 和图片地址。
- 属性含义依据 [MDN img 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img#referrerpolicy)。
- HTTP 对照已验证无 Referer 请求可以取得有效图片；自动浏览器访问权限仍未开放，因此页面实际效果交由用户刷新验证，不能将 HTTP 验证等同于浏览器端回归测试。
