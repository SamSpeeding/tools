# 影视目录采集设计

## 已确认范围

- 在 `/Users/tt/Desktop/4k/` 工作，交付两个 `.command` 入口，分别采集影视资料、下载封面。
- 电影分类 1 输出 `movies.json`，剧集分类 3 输出 `series.json`；顶层均为数组。不采独立分类 40“4K蓝光原盘”。
- 按站内 ID 识别条目，不合并不同季或同名文章。跨两个分类的条目在两个文件中分别保留。
- `preview.json` 的字段与真实磁力地址已获用户认可。正式简介保留网页原文，未知事实字段保存在 `extra_fields`，原始事实表保存在 `source_fields`。
- 实现完成后，先做离线行为测试、小样本真实验证，再运行全量采集和封面下载。

## 用户最新修订：只新增

此节取代前期关于修改时间增量、旧磁力合并更新和每 7 天复查的提议。

- 每次只通过 API 获取 ID 和分类清单。以对应本地 JSON 是否已有 ID 判断是否采集。
- 已有 ID 完全跳过：不取正文、不访问详情页、不对比修改时间、不更新任何影视资料。
- 只对新的 ID 获取 API 正文与关联媒体、标签，并访问详情网页提取磁力。
- 资源同时覆盖详情页新模块、旧正文锚点和纯文本 URI；API 正文有补充资源时按身份去重合并。网站原地址格式错误时保留原文并记录校验备注，不因一条错误地址漏掉整部影视资料。
- 不删除本地多余远端的记录，不检查远端条目是否已删除。
- 不设周期性复查，不设后台任务，不设强制资源刷新参数。
- 删除某一个 JSON 后，下次重新采集该文件对应分类；不存在能恢复旧影视记录的隐藏缓存。
- 每次遍历轻量 ID 清单，保证中断后仍可发现较旧漏项，不以遇到第一个已有条目作为结束条件。
- 输出按首次采集到的 `source_modified_at` 倒序，同时间按 ID 倒序。这个字段用于排序，不用于未来增量判断。

## 封面

- 读取两个 JSON 的 `cover.source_url`，同一图片地址已经下载成功就跳过。
- 多个条目共用图片 URL 时只下载一次，为每个条目建立各自带 ID 的图片文件名，避免文件名只能识别第一个条目。
- 文件名由类型、站内 ID、片名和图片 URL 短哈希组成，扩展名依据下载内容识别。
- 通过 `.state/images.json` 或文件名哈希恢复已下载图片的对应关系；删除影视 JSON 后仍可复用图片。
- 没有自动更换封面的行为。手动重采集后得到不同图片 URL 时下载新图，保留旧图。
- 检查图片签名、明显截断及请求完整性，不把错误页面当作图片保存。
- 仅更新封面本地路径、实际格式和已下载状态，其余影视字段不改动。

## 文件与错误恢复

- Python 标准库实现，网络使用 macOS 自带 curl，无第三方 Python 依赖。
- 两个 JSON 是影视记录唯一依据；`.state` 仅包含图片索引、运行统计、失败报告和锁文件。
- 正文与资源解析成功后入库；抓取失败的 ID 不保存空记录，下次会继续尝试。
- 正常详情页没有磁力时可入库，并在 `source_notes` 中说明；根据只新增规则以后不自动补资源。
- 每完成 10 个详情保存进度；临时文件写完再原子替换目标 JSON，避免中断写坏文件。
- 共用文件锁，防止两个任务并发写入同一 JSON。已有无效 JSON 会报错停止，不静默清空。
- 默认 3 个请求并发，全局请求间隔至少 0.2 秒。临时故障重试和退避，永久 HTTP 错误记录失败。
- 日志写入 `logs/`；双击完成后保留结果，等待回车退出。

## 核实事实

- 公开文章接口：`/wp-json/wp/v2/posts/{id}`，API 每页最多 100 条。
- 分类 1 为电影，3 为剧集；独立分类 40 为蓝光原盘，其已检查的唯一条目 54659 是许巍演唱会。
- 抽查的 API 正文没有磁力模块；详情网页 `.magnet-links` 中有资源名称和磁力地址。
- `title.rendered` 包含 HTML 实体，正文包含段落、换行、图片与影片事实字段，需要分别解析。
- `_embed=wp:featuredmedia,wp:term` 提供媒体和分类、标签；正文首张图片可作为封面备用。
- 分类名的“4K”不能用来推断每一个资源版本的分辨率。

## 验证目标

- 已有条目不请求正文或详情，不因远端修改或消失而改变本地记录。
- 删除单个 JSON 只重采对应分类，另一个文件保持不变。
- 抓取失败可在下次补齐；首次只采少量样本后，正常运行会继续补齐旧 ID。
- 重跑封面任务不产生重复下载；JSON 重建后仍能复用已有图片。
- 无效 JSON、错误图片、登录或防护页面不会被当作有效数据覆盖本地文件。
