# 影视资料与封面归档

## 资源浏览页面

`index.php` 提供深色电影 / 剧集目录、分类内搜索、每页 24 条分页，以及按需打开的资源详情面板。

- **部署只需三个文件**：`index.php`、`movies.json`、`series.json` 放在同一目录。需要 PHP 8.1+，无需数据库、Composer、前端构建或 `img` 目录。PHP 进程必须有权限读取两份 JSON。
- 搜索片名、原名、别名、导演、演员和标签；多个关键词以空格分隔时需全部匹配。保留 JSON 原有顺序。
- 封面仅通过 `<img>` 直连 `cover.download_url`（缺少时取 `source_url`），并设置 `referrerpolicy="no-referrer"`，避免外站来源信息导致部分封面返回 404。加载失败就显示内置占位，不使用图片代理。
- 点击卡片查看简介和资源版本，复制磁力或唤起设备上的下载工具。无效的来源链接只提示格式有误，不提供下载按钮。
- 关闭详情保留搜索、页码和滚动位置；支持 Esc、浏览器返回以及带条目参数的分享链接。
- 页面只读 JSON。服务器按所选分类读取和搜索，浏览器仅接收当前页；详情点击后单独请求，不会将整库传给前端。
- JSON 文件缺失或损坏时显示错误，不会改写或清空数据。暂无资源的条目依然可浏览。

本地预览：

```bash
cd /Users/tt/Desktop/4k
php -S 127.0.0.1:8740
```

然后访问 `http://127.0.0.1:8740/index.php`。PHP 内置服务器用于本地预览；部署时使用支持 PHP 的网站服务。

## 资料采集

双击以下两个文件即可使用，工作目录固定为脚本所在文件夹：

1. **同步影视资料.command**：把新电影写入 `movies.json`，新剧集写入 `series.json`。
2. **下载封面.command**：读取这两个 JSON，将缺少的封面保存到 `img/`。

运行结束后显示结果，按回车退出。两个任务共用文件锁，请依次执行。

## 同步规则

- **只新增，不更新**。通过站内 ID 判断条目是否已存在于相应 JSON；已有条目的正文、磁力、修改时间都不再请求或对比。
- 每次通过 API 分页读取轻量的 **ID 与分类清单**，然后只获取缺少条目的正文和详情网页。约两千条目录只需约二十余页 ID 清单，而不是访问两千个详情页。这也能在中断后补齐较旧的漏项。
- 电影分类为 1，剧集分类为 3，不包括独立的蓝光原盘分类 40。跨两个分类的条目在两个 JSON 中分别出现，每个文件内部按 ID 去重。
- API 提供正文、封面、分类、标签；详情网页提供磁力及资源名称。字段来自网站，资源参数按资源描述解析，并未读取影片文件核实。
- 兼容新资源模块、旧正文链接及未做成超链接的纯文本磁力，并补充 API 正文中的资源。网站原地址格式有误时原样保存，以 `url_valid: false`、`validation_error` 和条目备注说明，不擅自修改地址。
- 若网页超链接目标拼错、但显示文字中有完整且格式正确的磁力，则使用这段原文作为 `url`，并用 `source_href` 保留原来的超链接目标。
- 本地已有、网站撤下的条目和磁力继续保留。没有 7 天复查，没有定时任务，没有修改时间增量游标。
- 每个 JSON 顶层为数组，按采集时的 `source_modified_at` 倒序，同时间按 ID 倒序。排序不意味着以后会重新检查该时间。
- 正文与资源成功解析后才保存该条目。失败的 ID 不占位，下次运行继续尝试。正常详情页没有磁力时也会保存，并在 `source_notes` 里说明。
- 每完成 10 个详情保存一次进度，并在正常结束或收到 Ctrl-C 时保存已处理结果。强制杀死进程最多需要重做当前尚未保存的批次。
- JSON 使用临时文件完整写入后再替换；损坏的已有 JSON 会报错停止，不会被静默清空。

## 重新采集

**JSON 本身就是采集依据，没有隐藏的影视数据缓存。**

- 删除 `movies.json`：下次重新采集全部电影。
- 删除 `series.json`：下次重新采集全部剧集。
- 删除两个 JSON：下次重新采集全部电影和剧集。
- 只想更新某一条时，可以从对应 JSON 数组中移除该 ID 的整条记录，再运行同步脚本。文件须保持有效 JSON。

删除前如需保留远端已下架的旧记录，请先自行备份 JSON；重新采集只能获取远端仍然提供的条目。

## 封面规则

- 文件名：`类型_站内ID_片名_图片URL短哈希.真实格式`。
- 已存在且通过图片结构检查的文件直接复用，不重复下载。同一图片 URL 只下载一次；不同条目使用各自带 ID 的文件名复用图片内容。
- 重新采集 JSON 后，仍可通过图片索引或文件名中的 URL 哈希识别已经下载的封面。只有删除图片文件才会重新下载它。
- 普通资料同步不会更新已有条目的封面 URL。手动重采集得到新封面 URL 后，封面脚本会保存新图，旧图保留。
- 下载成功后更新 `cover.local_path`、`cover.downloaded` 和 `cover.format`；其他影视资料保持不变。
- `cover.local_path` 是相对于本目录的路径。`downloaded` 是上一次封面任务保存的状态，若手动删除图片，下次执行封面脚本会检查实际文件。
- 不下载电影视频，不连接 BT 网络，不测试磁力活跃度。
- 旧域名 `4kbt.net` 的图片会尝试当前域名 `4kbt.org`；旧年月上传路径失效时，再尝试同文件名的当前上传路径。只有响应确认为图片才保存。原始 `source_url` 保留，实际使用地址记录在 `download_url`。

## 目录

```text
同步影视资料.command
下载封面.command
collector.py                 # 执行入口
catalog_parser.py            # 解析正文与资源
catalog_io.py                # 请求、文件与图片检查
movies.json                  # 电影数组
series.json                  # 剧集数组
img/                         # 已下载封面
logs/                        # 每次运行的日志
.state/images.json           # 图片 URL 与文件对应索引
.state/last-sync.json         # 最近资料任务统计、失败清单
.state/last-covers.json       # 最近封面任务统计、失败清单
preview.json                 # 最初的结构样本，不参与同步
```

`.state/` 不保存影视正文，不会在 JSON 删除后恢复旧记录。

本次完整采集的数量、重复执行验证及来源数据缺失项见 [验证记录](docs/validation.md)。

## 命令行

需要 Python 3.10+ 和 macOS 自带的 curl。此电脑已具备，无第三方 Python 依赖。

```bash
cd /Users/tt/Desktop/4k
./同步影视资料.command
./下载封面.command

# 可选：只新增 3 个 ID，随后正常执行会补齐其他缺少的条目
python3 collector.py sync --limit 3
# 可选：降为单线程并放慢请求
python3 collector.py sync --workers 1 --interval 1
# 可选：在独立目录验证，不影响正式 JSON
python3 collector.py sync --output-dir /tmp/4k-sample --limit 2
# 行为测试（离线）
python3 -m unittest discover -s tests -v
```

默认 3 个并发请求，全局请求启动间隔至少 0.2 秒；连接超时 10 秒，单次请求最多 35 秒，临时失败最多尝试 3 次。退出码：0 成功；2 部分失败；1 配置或整体失败；130 用户中断。部分失败时查看日志和 `.state` 报告，之后重跑即可补齐未入库条目或未下载图片。
