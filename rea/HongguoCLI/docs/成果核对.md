## 请求和服务边界

当前配置的平台 baseURL 为 `https://api5-normal-sinfonlinec.fqnovel.com`。搜索到视频模型涉及：

1. `/reading/bookapi/search/tab/v`：关键词搜索得到 `series_id`。
2. `/novel/player/multi_video_detail/v1/`：得到全剧详情和每集 `vid`。
3. `/novel/player/multi_video_model/v1/`：得到各清晰度 URL、文件校验字段和加密参数。

无缓存、搜索一页、模型每批 5 集时，N 集地址导出通常需要 `1 + 1 + ceil(N/5)` 个平台请求，每个另需一次本地签名请求。真正下载再向模型返回的 CDN URL 发 GET；分页、重试、按 ID 跳过搜索会改变次数。当前实现见 [hongguo_api.py](../hongguo_api.py) 和 [hongguo.py](../hongguo.py)。

| 服务 | 所处位置与作用 |
|---|---|
| `fqnovel.com` 下配置的 API host | 平台内容接口；不是下载器作者的 explorer 服务。 |
| `hongguoduanju.com` | 红果短剧的官方公开网页来源，原程序用于网页搜索、预览和榜单；与下载器作者服务分开。当前 CLI 主链路未使用它。 |
| 模型返回的媒体 CDN | 读取视频文件；URL 会过期，地址可读不代表原文件已经解密。 |
| `127.0.0.1:临时端口` | 本机签名进程。复用 `unidbg-sign.jar`、两份 SO 和 BIN；可改造为其他本地调用接口，但这项重写尚未实施。 |
| 下载器本地 `/dl/*` | 原 FastAPI 业务接口；其处理函数决定后续访问哪里，不能仅凭 `/dl` 路径认定全部指向第三方。 |
| `explorer.hongguodownloader.com` | 作者维护的远端 Catalog；`/genres`、`/explorer` 与平台 `/reading/*` 分开记录。原本地 `_explorer_catalog()` 另有读取打包目录文件的分支。 |
| `api.hongguodownloader.com` 等作者域名 | 原程序许可、支付等服务；当前 CLI 核心链路不使用这些许可/支付模块。 |

2026-10-13 补充核实域名分类：[hongguoduanju.com 首页](https://hongguoduanju.com/)标示红果短剧官网，页脚列北京笔墨留香科技有限公司、备案及 `bytedance.com` 举报邮箱；[hongguodownloader.com 首页](https://hongguodownloader.com/)介绍的是另一个 Windows 下载器。两者不能一概归为下载器作者的第三方封装服务。在本项目架构中，前者可归为“可选的官方网页数据源”，后者可归为“原下载器的第三方目录及商业服务”；授权和支付不属于用户偏好设置。

本地 HTTP 是可替换的调用方式，不是必须保留的业务协议。当前 CLI 已通过代码直接组织业务，不启动原来的 70 路由 FastAPI 服务；相应的请求编排、选集、文件处理等逻辑仍然存在。签名器 HTTP 层也可以另行改造成本机进程通信或 Java 内部调用，但 Java/unidbg/SO 的签名计算不能随 HTTP 层一起省略；目前尚未实施该改造。

文档计数采用不同口径，不相加当成“官方接口总数”：

- 本地显式业务接口 **70 个 method/path，67 个唯一路径**：GET 40、POST 29、DELETE 1。安装模式过滤放行其中 50 项，另外 20 项被屏蔽；框架文档接口另有 8 个 method/path。
- 出站路径/模板 **33 项**：App 8、网页 7、分享 2、Catalog 2、许可 5、支付 4、更新 2、可配置签名辅助 2、媒体 1。Java signer 单列。
- 8 个 App 路径包含核心 3 个，以及 suggest、plan、collection、rank、category。全部被文档覆盖不等于全部实测通过。

原本地接口独立枚举与清单比对为 0 缺失、0 多出；出站审计的固定 App 路径也没有集合差异。证据：[本地审计](../../analysis/evidence/api-audit.md)、[出站审计](../../analysis/evidence/remote-routes-audit.json)。公开网页 SSR 备用链已记录，但其 `accessible_episode_cnt` 限制仍适用；当前 CLI 没有承诺提供完整网页回退模式。

## 授权和设备

原下载器通过许可 RPC 控制下载准入，激活码关联设备，不是已证明的多人账号登录系统。具体 RPC、nonce 和响应签名字段已经记录在 [REMOTE_API](../../analysis/REMOTE_API.md)“许可”及“许可响应认证与支付边界”章节。以下为原包静态结论，本次没有激活、解绑或变更任何真实许可。

- Windows 优先读取 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`，加 `mg:` 前缀后计算 SHA-256，取前 32 个十六进制字符，再加 `d1:` 得到设备 ID。读取失败时复用本地状态中的 ID，或生成并保存 `r1:` UUID。证据：[licensing.dis.txt](../../analysis/evidence/licensing.dis.txt) 的 `_machine_guid`（1290 行）、`device_id`（2151 行）。
- 激活请求带 `p_device` 和 `p_device_label` 等字段；标签来自主机名和用户名。可确认发送摘要及标签，不能据此认定服务端掌握全部硬件信息或已经恢复其数据库结构。证据为同文件 `device_label`（2290 行）和远端 API 的 activate_key 参数。
- 同一 Windows 系统仅卸载重装，MachineGuid 通常不变，这是指纹算法推断。能否自动恢复许可还取决于本地 `license.json` 中 key/secret 是否保留和服务端状态；没有做实际重装验证。重装系统、读注册表失败、删除 UUID 回退状态的情况不能作相同保证。
- 包内前端提示：释放当前 PC 后在另一台用同一 key 激活，每 7 天一次，并处理服务端 `cooldown/next_move_allowed_at`。这是客户端规则与响应处理证据，不是服务端强制执行的实测。见 [downloader.js](../../analysis/ui/downloader.js) 2052、2075 行。
- 同时设备数来自响应的 `max_devices/devices_used/device_count`，见同文件 2003 行。此前“一台设备”的网站套餐说法不应扩写为所有许可永久固定一台，具体套餐仍以服务端返回为准。

当前 CLI 的代码路径不调用原下载器许可/支付模块，已验证样本的搜索、详情、模型、下载和解密可独立完成。这个结果不等于破解了许可服务器、获取了正版许可，也不保证平台所有内容或未来协议均可用。签名 Jar 与原生库仍为实际依赖。

## 支付调查

从原包可确认的流程是：作者后端提供套餐与 Checkout 创建、订单轮询、账单门户接口；程序校验支付 URL 后用浏览器打开 Stripe Checkout/Billing 等允许域名。客户端并未包含据此可确认的 Stripe 商户后台身份或收款账户资料。详见 [REMOTE_API](../../analysis/REMOTE_API.md) 支付章节，以及 [包内前端](../../analysis/ui/downloader.js) 的 `manageBilling`。

Stripe 支持符合条件的 sole proprietor / individual 类型；它们仍需满足所在地区及身份核验条件，不能理解为任意地区仅靠个人邮箱即可收款。2026-10-13 复核的官方资料包括 [sole proprietor 注册说明](https://support.stripe.com/questions/signing-up-for-stripe-as-a-sole-proprietor-without-employer-id-number)、[美国账户要求](https://support.stripe.com/questions/requirements-for-having-a-us-stripe-account?locale=en-GB) 和 [全球支持地区](https://stripe.com/global)。本次取得的是检索工具返回的官方正文，前两项直接 open 返回错误；未进行账户注册资格验证。

## 原程序和未来架构

原工件为 Inno Setup 6.7.0 安装器，内含 Python 3.11 运行环境。Python 应用使用 FastAPI/Uvicorn 提供本地网页服务，HTML/JS 构成界面，启动器选择 Edge/Chrome 的 `--app=` 模式和独立浏览器 profile，失败时回退默认浏览器。证据：[安装器清单](../../analysis/evidence/installer-manifest.json) 的 Python 文件、[server.dis.txt](../../analysis/evidence/server.dis.txt) 3197 行、[app.dis.txt](../../analysis/evidence/app.dis.txt) 11891 与 12621 行、[提取工具](../../analysis/tools/innoextract.py)。原 Windows EXE 未在本机实际运行，这些是打包文件及启动代码结论。

未来跨平台应用的讨论方案为 **Tauri 2 + Vue/TypeScript + Rust 窗口与进程管理 + Python worker**，通过 JSON stdin/stdout 通信；任务/设置可用 SQLite。v1 暂不接账户和支付。这是方案讨论，尚无该桌面项目、安装包或 Windows 验收结果。

Tauri 使用系统 WebView，默认不自带 Node.js；Python/Java/FFmpeg 或 Node 后端需另行随应用打包，所以壳小不等于包含全部依赖后的安装包也很小。官方依据：[Tauri 架构](https://v2.tauri.app/concept/architecture/)、[外部程序打包](https://v2.tauri.app/develop/sidecar/)、[Node sidecar](https://v2.tauri.app/learn/sidecar-nodejs/)，2026-10-13 复核。该混合架构是本项目的建议，不是原程序采用 Tauri 的证据。

当前 `HongguoCLI` 的随目录 Python 运行时为 macOS ARM64，Java 17+、FFmpeg 和 ffprobe 使用本机安装；不是完全自包含的跨平台发行包。Python 后端加原生网页、PHP 方案曾作比较，随后网页项目被取消；当前没有继续构建它们的待办。
