# 红果命令行下载

双击 **启动.command**，输入关键词、选择剧，再输入要下载的集号。成品是已经解密并校验过的 MP4。

2026-10-14：新增独立 `hongguo_hm/`，视频模型请求只替换本次 Helios / Medusa，保留原设备、参数和 JAR 其余签名。模块运行不引用参考脚本或实验目录，也不发网络请求；Java/JAR/SO 仍用于其他签名。详见 [本地签名说明](docs/本地签名.md)。

从安装包逆向到当前脚本的成果、证据位置、已清理的历史输出及尚未验证范围，统一见 [成果核对](docs/成果核对.md)。原 `analysis` 继续保持不变。

关于去掉 Python、改用 Node.js 管理签名和完成下载解密，见 [Node 迁移可行性调研](docs/Node迁移可行性.md)；当前交付仍为 Python 版本。

PHP 方案的能力、网络传输、解密移植及跨平台任务管理分析，见 [PHP 迁移可行性调研](docs/PHP迁移可行性.md)。该方案仅完成调研。

```text
输入剧名或关键词：坠崖捡个参娃娃
选择剧的序号：1
下载集号：1,3-5
```

集号支持 `1`、`1,3,5`、`2-6`、`1,3-5`、`all`（全部）。重复集号自动去重；不存在的集号会提示重新输入。输入 `q` 退出，**直接回车则只导出全剧信息和全部下载地址**。

搜索默认先读取一页；服务器还有结果时，选剧提示中会出现 **`n 下一页`**。输入 `n` 追加结果，已有序号保持不变、重复剧自动去重。返回结果中的榜单与视频关联剧也会展开，并标注“榜单推荐”“视频关联”。这类推荐不保证剧名包含关键词。`--pages 3` 可在开始时读取三页，范围 1–12；页数和平台全部剧目数量不是一回事。

## 命令行

在本目录运行：

```bash
# 交互搜索、选剧、选集
.venv/bin/python hongguo.py

# 搜索后选第一个结果，下载指定集数
.venv/bin/python hongguo.py "坠崖捡个参娃娃" --select 1 --download "1,3-5"

# 按剧 ID 下载，跳过搜索
.venv/bin/python hongguo.py --series-id 7689863296106646590 --download "2-6"

# 720p，下载全部集数
.venv/bin/python hongguo.py "坠崖捡个参娃娃" --select 1 --download all --quality 720p

# 保留原来的信息和地址导出功能
.venv/bin/python hongguo.py "逆袭" --select 1 --export-only

# 只看搜索结果；结果不足可以增加搜索页数
.venv/bin/python hongguo.py "逆袭" --pages 3 --list-only
```

默认清晰度 `1080p`；可选 `720p/540p/480p/360p`。指定清晰度缺失时明确报错，不会悄悄改为另一档。

## 输出与恢复

- 视频：`downloads/剧名_ID/第001集_1080p.mp4`。
- 每集同名 `.json`：成品 SHA-256、轨道信息及完整解码验证结果，不保存内容密钥。
- 同目录 `下载记录.json`：本次选集、每集成功／失败状态和文件位置，保留其他集数的历史记录。
- 地址导出：`outputs/剧名_ID.json`、同名 `.txt`，包含原始剧信息与全部清晰度地址。
- 签名器日志：运行期间写入 `outputs/signer-进程号.log`；任务成功后自动删除，发生错误、部分失败或中断时保留并显示路径。

`--download-dir /路径` 改变视频目录；`--output /目录或文件.json` 仅改变信息导出位置。显式 `--download` 只查询所选集数的视频模型，不先请求整部剧的全部地址。

下载逐集执行，实时显示进度。主地址失败会尝试备用地址，再刷新该集模型重试一次。源文件经过大小、哈希校验；解密后检查完整音视频解码，全部通过才生成最终文件。URL 和解密参数始终使用同一份模型。

已完成文件与同名验证记录匹配时自动跳过。已有文件无法通过匹配校验时拒绝覆盖。按 `Ctrl+C` 可中止；已完成视频保留，未完成的临时文件会清理。重新运行相同选集即可继续，暂不支持单个文件的断点续传。

退出码：`0` 完成，`2` 部分失败，`1` 启动或请求错误，`130` 用户中断。非交互运行且未指定 `--download` 时维持原来的地址导出行为。

```text
  hongguo_signer.py      # 本地签名进程管理
  hongguo_hm/            # 本地生成模型请求的 Helios / Medusa（含协议数据表）

  vendor/               # 签名 Jar、原生库、解密源码与原始字节码、校验清单
  .runtime/python/      # 本机 macOS ARM64 Python 3.11 运行时
  .venv/                # 本项目的 Python 依赖
  tests/                # 离线测试

  outputs/              # 导出或运行日志，自动创建
```

日常运行不读取上级 `analysis`，也不需要 Windows 安装包。签名仍在本机临时端口运行，由脚本启动和关闭；不是远程第三方签名服务。

当前 Mac 环境已准备好，默认运行时和安装脚本仍使用已验证的 **Python 3.11**。下载流程现已调用解密 `.py` 源码，不再要求执行原始字节码；与原 `.pyc` 做差分测试时仍需要 Python 3.11。其他 Python 版本尚未完成完整验证。Java 17+、FFmpeg 和 ffprobe 使用本机安装的版本（支持 PATH、Apple Silicon Homebrew 常用路径），没有将它们打包到项目中。

移动项目后若虚拟环境路径失效，双击 `安装依赖.command` 重建。此操作需要联网安装 `requirements.txt`；随目录的 Python 运行时用于 macOS ARM64，其他平台应自行准备 Python 3.11、Java 17+ 和 FFmpeg。

`vendor` 中保留了来自安装包的 8 个原始文件，另外新增 4 个从解密字节码重建的 `.py`；SHA-256 均记录在 `vendor/manifest.json`。签名继续由原 Jar/原生库生成基础结果，视频模型请求的 Helios / Medusa 再由 `hongguo_hm/` 本地替换；解密使用可读 Python 实现，不加载原 `.pyc`。当前已验证 CENC-AES-CTR 的 HEVC 视频与 AAC 音频；其他加密格式或视频编码会报不支持。

### 视频解密流程

1. 查询所选集的视频模型，取得对应清晰度的 URL、文件大小、哈希，以及 `encrypt_info` 中的加密方法和 `spade_a`。
2. 下载加密 MP4，检查文件大小与哈希。URL 与加密参数必须来自同一份模型。
3. `unwrap_spade.py` 从 `spade_a` 解析内容密钥；`decutil` 读取 MP4 内的样本 IV，`oracle` 检验密钥和 IV 是否与文件匹配。
4. `decutil.py` 按 CENC AES-CTR 解密视频和音频样本，检查视频样本，清除 MP4 加密标记。
5. FFmpeg 以流复制方式重新封装，设置 HEVC 的 `hvc1` 标签和快速起播信息，不重新压缩视频。ffprobe 检查轨道和时长，FFmpeg 完整解码检查；通过后才保存最终 MP4。

解密源码位于 `vendor/decrypt/`：`unwrap_spade.py`、`oracle.py`、`decutil.py`、`extract_keybox_pairs.py`。同目录的 4 个原 `.pyc` 全部保留，内容未改。运行需要 Python、PyCryptodome、FFmpeg 和 ffprobe，入口代码是 `hongguo_download.py` 的 `playable_file()`。

这 4 份源码是根据字节码恢复的可读实现，并非作者原始源文件；保留了全部原函数、常量及命令行入口。`oracle` 内的 ADB/设备分析工具也保留，但正常导入和下载解密不会调用它们。源码内部没有通过 `marshal`、`exec` 或加载原 `.pyc` 代替实现。

下载前会校验 4 个 `.py` 的 SHA-256，加载时检查实际模块路径；缺少源码会报错，不会悄悄回退到原 `.pyc`。维护时修改源码后，需要同步更新 `vendor/manifest.json` 中对应 `.py` 的哈希；原 `.pyc` 的记录用于保留原始文件身份。正常 Python 导入可能产生 `__pycache__`，它是新源码的缓存，与保留的原 `.pyc` 不同。

签名 Jar 和原生库用于前面的接口请求；已有加密文件和匹配的模型参数后，媒体解密在本地进行，无须访问远程解密服务。仅有下载 URL 不够。内容密钥不写入成品验证记录，过程中的加密文件和中间 MP4 自动清理。
