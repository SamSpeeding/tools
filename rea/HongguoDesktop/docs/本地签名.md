# 视频模型的本地 Helios / Medusa

2026-10-14。桌面项目和 `HongguoCLI` 使用同一份独立 Python 模块 `hongguo_hm/`。依据已核对的协议和参考算法整理、精简并适配本项目；不是调用参考脚本，也不宣称这些协议算法是我们原创设计。

## 当前请求流程

1. 沿用原 `config.json` 与选定设备，构造最终 URL 和 UTF-8 JSON 正文。桌面仍用 `devices.json[0]`；CLI 仍默认索引 0，并保留 `--device-index` 的原有行为。
2. 按最终正文计算 `x-ss-stub`，让原本机 JAR 生成原来的八个签名头。
3. **只在下列两个视频模型路径**，从 JAR 结果读取 `x-khronos`，用最终 URL、正文 bytes 和该时间戳，在 Python 中重新生成 `x-helios`、`x-medusa`，覆盖同名头。
4. 其余六个 JAR 头 `x-argus`、`x-gorgon`、`x-khronos`、`x-ladon`、`x-neptune`、`x-soter` 保持原值，发送原请求。

| 生效路径 | 用途 |
| --- | --- |
| `/novel/player/multi_video_model/v1/` | 批量视频模型 |
| `/novel/player/video_model/v1/` | 单个视频模型 |

搜索、榜单、分类和剧详情继续使用原 JAR 签名。平台 base URL 仍是 `https://api5-normal-sinfonlinec.fqnovel.com`，没有切换到网页或作者服务。

“复用原请求”指沿用请求构造、设备与参数，不是重放以前保存的签名。每次请求重新生成随机数和签名；本模块不再次读取系统时间，不重新排序/编码 query，不重新序列化正文，也不随机生成 DID/IID。Medusa 内的环境报告时间也使用本次 `x-khronos`。

桌面仍在播放/下载等实际需要模型的动作时获取模型，先 `multi_video_model`，失败再尝试 `video_model`，界面继续显示实际选中的接口。浏览找剧和查看详情不会提前请求模型。CLI 保持每批最多 5 个 VID 的地址查询/导出逻辑；显式选集下载只查询所选分集。此次没有给 CLI 新增单接口回退。

## 独立模块与调用

| 文件 | 职责 |
| --- | --- |
| `hongguo_hm/__init__.py` | 输入校验、Helios、Medusa protobuf、请求绑定、混合和封装 |
| `hongguo_hm/_primitives.py` | 标准 SM3、自定义 Medusa v3 运算、三个 f13 分支 |
| `hongguo_hm/medusa-v3-table.bin` | 81,936 字节的协议查找表，非可执行文件 |

桌面模块位于 `backend/hongguo_hm/`，CLI 位于根目录 `hongguo_hm/`。两份独立复制、内容一致，各项目可单独移动。Mac 构建会将完整模块和数据表随 `backend/` 打入 `.app`。查找表第一次使用时校验长度及 SHA-256：

`239ddf955d14a008311b8c3adcf05713b858954068fff02ab19c2ba81e31d1d3`

核心接口：

```python
from hongguo_hm import generate_headers, model_headers

# 直接生成：只返回两个头；khronos 必须来自本次 JAR 签名。
pair = generate_headers(final_url, final_body_bytes, khronos)

# 生产入口使用这一层，额外校验 JAR 时间戳和正文 stub。
# headers 已含原 JAR 签名，键名已转小写。
headers.update(model_headers(final_url, final_body_bytes, headers))
```

模块自身只依赖 Python 标准库，不使用 `requests`、JAR、SO、网络或 `.pyc`，不引用 `/Users/tt/Downloads/红果短剧.py` 或实验目录。运行整个应用/CLI **仍需要原 JAR、SO、Java 和现有 Python 网络/解密依赖**，因为其余签名仍由原签名器负责。没有增加 Python 第三方依赖。

仅保留两个头的生成能力。参考脚本的网页抓取、TVBox 插件、设备生成、下载、解密、播放服务器、其他四个头的计算，以及签名的反向解码均未移入本模块。大查找表保留为独立数据，不能为了代码短而删掉某个摘要分支。

## 协议选择及错误处理

- 当前仅支持经验证的 `aid=8662` 上下文。Helios 明文是 `khronos-1588093228-8662`；中间字段是平台签名协议的 license ID，与原下载器付费激活码无关。
- Medusa 使用 v3 包装和已验证的 SDK/环境模板。保留参考算法中的固定电量、容量、历史采样时间等字段；这些不是本机 Mac 的真实指纹，也不构成完成设备注册的证据。设备 ID、App 版本、机型、品牌、系统版本从最终 URL 读取。
- 原 JAR 的 Medusa v4 内层仍未还原。本实现不修改 JAR 内部上下文、不声称已修复或复现 v4。
- 签名覆盖原始 query、正文摘要和时间；没有 body 时使用协议规定的零摘要。生产模型请求始终传入最终 JSON bytes。
- 缺少/非法时间戳、正文 stub 不匹配、必要设备字段缺失、aid 不支持、重复 query 参数、数据表缺失/损坏时，模型请求在发给平台前失败，错误标记为 `signer`。不会悄悄退回已知失败的 JAR H/M。
- 随机值为逐调用局部数据，不 monkeypatch 全局时间或随机源，适用于后台并发请求。

## 验证与维护

`tests/test_hm.py` 使用保存的**合成设备**测试向量，不导入参考文件。64 组向量覆盖 4 种时间戳低位分支 × 16 种 f13 IV 选择，逐字节比较两份头；同时检查标准 SM3、URL 编码/正文/设备/IID 变化、并发独立性和表损坏。

`tests/test_model_signatures.py` 通过真正的 `_api_once` 入口核对只替换两个头、保留其余签名、URL/body 完全一致、不同模型路径和非模型路径的边界，以及签名异常时不发送请求。桌面原有模型回退测试继续覆盖“批量成功不调用单接口”和失败回退。
