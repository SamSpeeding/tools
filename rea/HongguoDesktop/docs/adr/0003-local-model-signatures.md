# 保留 JAR 签名链，只本地替换模型请求的 Helios / Medusa

2026-10-14，用户批准将固定设备 + 原请求参数 + 本地 Helios/Medusa 的实验结果接入桌面项目和 CLI，并要求独立精简模块，不在运行时调用参考脚本。

原设备使用 JAR 全签名请求批量模型得到 `110001`，只替换 H/M 后，在多集、多 VID 的受控实验中反复成功。Helios 的 license 字段差异已做单变量对照；只替换 Helios 仍失败。JAR Medusa v4 内层未知，因此直接实现已验证的 Medusa v3，不改 native 初始化，不随机换设备。

在 `HongguoAPI._api_once` 合并 JAR 结果后，只对批量/单个视频模型路径生成两个替代头。独立模块接受最终 URL、正文 bytes 与 JAR 的时间戳，避免二次编码、二次计时和全局 monkeypatch。输入异常明确中止，保留其余签名头及既有桌面回退。找剧接口和媒体解密流程保持原样。

模块在桌面和 CLI 各复制一份，维持两项目可独立移动；交付检查验证两份内容一致。查找表按数据随包分发，导入和签名只使用标准库。原 JAR/SO/Java 仍为其余签名服务。

细节、来源与测试见 [本地签名说明](../本地签名.md)。这是经实测的兼容实现，不是对官方稳定性、设备注册状态或 v4 内层的证明。
