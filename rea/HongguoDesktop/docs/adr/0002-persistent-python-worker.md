# 通过标准输入输出管理常驻 Python worker

Tauri 使用固定命令调用 Python worker，JSONL 协议承载请求、响应和进度事件。内容查询在线程池运行；队列与设置命令按输入顺序处理；媒体下载由独立线程串行执行。任务事件携带递增 revision，防止异步响应覆盖更新的进度。

这一方案复用已验证的 Python 媒体链路，并将可写状态放在应用包外。业务命令不需要 Python HTTP 服务器和端口发现，但需要 Rust 管理 worker 的输入输出、请求超时及进程退出。原 Java 签名器仍通过本机带令牌的回环服务调用，一个应用生命周期复用一个签名器。

2026-10-13 用户追加分集流式播放：业务命令仍走上述 JSONL；媒体另由 worker 的回环 HTTP 服务向 WebView 提供 HEAD/GET/Range。服务仅监听 127.0.0.1 随机端口，路径使用随机会话令牌；只提供已从当前详情选定的分集，不接受任意上游 URL。准备模型在线程池运行，停止、切集及队列命令仍保持响应。前端以请求 ID 和 revision 丢弃旧事件，关闭或退出时释放会话、缓存与服务。此扩展不替换下载的完整性和 FFmpeg 校验。

退出时先由界面确认未完成任务，保存中断记录并取消当前处理；Rust 限时等待后清理整个进程组。Mac 额外实现 applicationShouldTerminate，用于菜单／快捷键和 Dock 的原生退出路径；普通窗口关闭由 Tauri 事件处理。强制结束应用或系统断电无法显示确认，但下次启动不会自动续传。

仅验证当前 macOS ARM64 构建；Windows 的运行时打包、进程树处理和退出行为必须单独实现与验收。
