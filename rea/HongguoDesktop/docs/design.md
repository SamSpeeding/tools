## 后续追加：分集流式播放

2026-10-13 用户要求每集可播放，并流式返回已经解密的数据。采用详情每集新增播放按钮、独立播放器弹层和原生 video 控件；提供选集、上下集、画质、暂停、拖动和手动重试，不自动连播或永久保存播放文件。

复用原 App API、设备池第0组、JAR/SO签名与恢复出的 unwrap_spade.py 解密材料计算。独立编写有边界检查的 MP4 索引解析和按字节范围 AES-CTR 处理，不把被研究的第三方 TVBox 脚本、网页内容接口、随机设备策略或 Python 签名实现引入应用。HTTP媒体服务只返回解密MP4；请求接口仍通过标准输入输出。

先读取 moov 索引与少量视频样本验证密钥，再向播放器提供按需读取；支持原文件 moov 位于首部或尾部。逐样本 IV、AES 块中间的 Range 起点、音视频轨和 CENC 子样本布局按索引处理；不支持的格式明确失败。分段 CDN 响应必须与请求范围、文件总大小一致，不悄悄退化成先下载整集。上游错误由原模型回退处理，媒体地址过期提示手动重试，不自动轮换设备。

## 实现方案与验收

已实现：Tauri 界面 → Rust 固定业务命令与进程管理 → 常驻 Python worker → 本地 Java 签名、App API、下载解密及 FFmpeg 校验。进度使用结构化事件回传，日志与运行数据写入包外可写目录。一个签名进程供本次应用生命周期复用；退出时清理 Python、Java、FFmpeg 子进程。原解密 pyc 保留在研究副本，应用包只带四个恢复出的 py 源码。

实施遵循本记录，不使用网页或作者数据源兜底。平台错误明确展示；不会将本地样本测试计为真实视频下载验收通过。

首轮验收：Finder 双击本机 `.app` 启动；四个找剧入口能展示真实 App 数据及按接口能力翻页；筛选更新游标；详情和分集正确；至少一集真实下载、解密、校验成功；任务串行执行且浏览保持响应；取消、重试、重复点击和退出流程符合最终决定；运行无需打开终端。
