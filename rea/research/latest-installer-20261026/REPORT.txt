结论
----
有明确的新适配，并已用现有固定设备短时在线验证成功。关键变化是新 GET
批量接口显式 signed=False，完全跳过本地签名器和签名头生成；配合下载队列
故障判断调整，签名器故障不再单独阻断可走此 GET 端点的解析任务。
JAR/SO、设备池、旧 POST 批量和单集接口的签名逻辑没有更新。
本轮确认的是新 GET 无签名方案可用；没有重测旧 POST，不能宣称它已恢复，
也不能据约 43 秒的实验声称永久稳定或整个原程序已不需要 Java。

作者如何改
----------
1. 新 GET 批量不再签名。
   URL：https://api5-normal-sinfonlinec.fqnovel.com/reading/bookapi/video_tab/multi_video_model/v1/
   _vm_tab_pass 源行2093的实际调用等价于：
     api('GET', _VM_TAB, extra_query=_vm_tab_query(chunk),
         signed=False, max_retries=2)
   旧版没有 signed=False，使用 api 的默认 signed=True。
   _api_once 源行510本身没改；signed=False 在偏移240–242跳过244–580：
   不检查 _signer_warm/signer_reachable，不调用 sign，不合并其返回的头。
   因包内 session_headers 也没有预置签名，此请求不带 x-helios、x-medusa、
   x-gorgon、x-argus、x-ladon、x-khronos 等签名头。
   仍保留基础 App/device query、UA、区域/SDK 头和当前 _rticket。

2. GET 恢复探测也改成不签名。
   _vm_alive 内第一条 lambda，源行2180，同样新增 signed=False。
   旧 POST 批量探测和单集探测仍保留默认签名。
   signed=False 还触发既有 api 行为：不把这条 GET 的风控/空模型错误按
   signed 路径计入 risk/empty 故障次数；连接故障的 network 处理仍存在。

3. 让签名器故障不再一律暂停模型解析/下载调度。
   新增 hongguo.resolve_down，源行739：
     return _src['down'] and _src['reason'] != 'signer'
   offline_dl 的 EpisodePool._take、_feed、_episode_task、dl_vid 改用此判断。
   _feed 仍保留 source_down 用于其他判断，并新增 res_down 控制暂停和取模型；
   不能描述为所有故障检查均被删除。risk/empty/network 故障仍会暂停。
   相关细节还有 series_episodes 对 signer 故障下备用元数据设置 web_only，
   _prepare 对 web_only 跳过封面/元数据保存。这是原程序容错配套，不属于
   GET 请求参数，也未带入我们限定 App API 的项目。

4. 这些部分没有变。
   调用顺序仍是 GET 新批量 → POST 旧批量 → POST 单集回退。
   每组最多5个仍是客户端分组限制，本轮没有重新测试服务端数量上限。
   GET query仍为：video_id=逗号连接VID、video_platform=1024、
   need_all_video_definition=true、device_level=3、detail_page_version=0。
   响应仍取 data.video_model_data[vid].video_model。
   旧 POST 仍 /novel/player/multi_video_model/v1/，
   body仍 biz_param + mixed_video_id_map:{"1":[vid,...]}，仍签名。
   单集仍 /novel/player/video_model/v1/，仍签名。
   _vm_lookup、_vm_entry、get_video_tracks/urls、缓存和回退算法未发生实质变更。
   之前发现的“存在条目但空 video_list 返回 None、不会加入回退”边界仍可复现。
